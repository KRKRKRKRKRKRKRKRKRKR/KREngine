# アニメーションの調整ツール KRAnimationEditor

骨つきのモデル(glTF = `.glb` / `.gltf`・FBX = `.fbx`)の**骨・動き・当たり判定の形**を、見て、調整して、保存するツール。調整した結果(`<モデル名>.hitboxes.json`)は、ゲームが `AnimatedModel` で**読み込むだけ**([Usage.md](Usage.md) の 7)。ゲームに、調整の画面は、要らない。

[← 資料の案内(Structure.md)に戻る](Structure.md)

## 起動
```
cmake --preset vs2026
cmake --build build --config Debug --target KRAnimationEditor
build/tools/AnimationEditor/Debug/KRAnimationEditor.exe [--assets <アセットのフォルダー>] [--model <Models からの相対パス>]
```
- **引数なし**:前回の続き(`KRAnimationEditor.txt` に記憶。exe の隣)。初めては、エンジンの `samples/Assets`。
- `--assets`:ゲームの `Assets` フォルダー(中に `Models/` があるフォルダー)。例:`--assets C:\SchoolProgram\Game\Suresurehikouki\Assets`。
- `--model`:`Models/` からの相対パス。例:`--model Boss/Boss.glb`。省略すると、一覧の最初のモデル。
- Visual Studio では、エンジン単体の `.slnx` を開くと、**KRAnimationEditor が、既定のスタートアップ**(F5 で動く)。

## 画面の見方(画面の文字は、日本語)
| 区画 | 項目 | 役割 |
|---|---|---|
| **プロジェクト** | アセット(文字欄・「最近...」・「参照...」) | 開くゲームの `Assets` フォルダー(中に `Models/` があるフォルダー)。文字欄に入れて Enter・「参照...」で選ぶ・「最近...」で、最近使ったフォルダー(最大 8 個)から選ぶ。`Models/` が無いフォルダーは、断られる |
| | モデル | `Assets/Models/` の下の `.glb` / `.gltf` / `.fbx` の一覧(拡張子も表示)。選ぶと開く。同名の `.glb` と `.fbx` は、`.glb` が先 |
| **表示** | 骨 / 骨を手前に表示 / メッシュ / モデルを回す | 骨の表示・骨をメッシュの手前に描く・メッシュの表示・モデルの自動回転 |
| | カメラをリセット | カメラを、最初の位置に戻す |
| | **骨の選択** | 骨を、名前の一覧から選ぶ(階層で字下げ)。選んだ骨が橙色になり、下の判定の形の調整の対象になる |
| **再生** | 動き | 動きを、名前の一覧から選ぶ |
| | 一時停止 / ループ / 速さ / 時刻 | 一時停止・ループ・速さ・時刻(止めて、動かすと、姿勢を確かめられる) |
| | 基準姿勢(アニメーションなし) | オンで、動きを止めて、基準姿勢にする。オフで、選んでいる動きを、最初から再生 |
| **当たり判定** | 判定の形を表示 | 判定の形(緑の箱・球。選んでいる形は黄・テストの箱に触れた形は赤)の表示 |
| | テストの箱の位置 | 水色の「テストの箱」の位置。判定の形にぶつけて、当たりを確かめる |
| | 形の種類 / 中心(骨の中) / 半分の大きさ(半径) | 選んだ骨の形の、種類(箱・球)・中心・大きさ(骨の中の座標。骨が動いても、数字は変わらない) |
| | この骨に判定の形を追加 / この形を削除 | 選んだ骨に、形を足す・消す(1 本の骨に、複数の形も付けられる。複数あるときは、「この骨の何番目の形」で選ぶ) |
| | **判定を保存** / 判定を読み直す | 保存・読み直し |

**マウス**:左ドラッグ = 回す / 中ドラッグ = 平行移動 / ホイール = 近づく・離れる / **左クリック = 形・骨を選ぶ**(ImGui の窓の上では、動かさない)。形を動かす・コピーするなどは、次の「画面の上で、直接操作する」。

## 画面の上で、直接操作する(ビューポート)
数字を打たなくても、3D の絵の上で、形を選んで、動かせる。

| やりたいこと | 操作 |
|---|---|
| **判定の形を選ぶ** | 形の上を、左クリック(動きが 4 ピクセル未満 = クリック。それ以上動かすと、ドラッグ = カメラを回す)。重なっているときは、**一番手前**の形。選んだ形は黄色・その骨は橙色になり、「骨の選択」も、その骨に変わる |
| **骨を選ぶ** | 形に当たらない所で、骨の線の近くを、左クリック(線までの距離が、モデルの半径の 6% 以内で、一番近い骨)。**形と骨が重なるときは、形が優先** |
| **形を動かす** | 選んだ形の中心に出る、移動のギズモ(赤 X・緑 Y・青 Z の矢印)を、ドラッグ。動かした量は、骨の中の座標に直されて `center` になる(動きを再生していても、骨について動く) |
| **形の大きさを変える** | **S キー**(スケール)で、大きさのギズモに切り替えて、ドラッグ。箱は `halfSize`(軸は、箱の向きにそろう)・球は `radius`。**最小値は 0.01**(小さくしすぎて、形が消えない) |
| 移動に戻す | **T キー**(Blender の「S = スケール」に合わせた。移動は、Blender では G だが、ここでは T) |
| コピー・貼り付け | **Ctrl+C / Ctrl+V**(または、ボタン)。貼り付けは、選んでいる骨に、形を 1 つ増やす。**同じ骨に貼るときは、少しずらす**(重なって見えなくならないように) |
| **左右反転して貼り付け** | コピーした形を、**X = 0 の鏡映し**にして、対の骨に貼る。対の骨は、**名前から自動**(下)。決まらなければ、「反転先の骨」の一覧から選ぶ |

- ギズモの上にマウスがあるとき・ドラッグ中は、カメラを回さず、クリックでも選ばない。ImGui の窓の上のクリックは、選ばない。文字を入力している間は、キー(T・S・Ctrl+C / V)も効かない。
- 形を動かす・大きさを変える・貼り付けると、「未保存」の印が付く(下の「未保存の変更」)。
- 「判定の形を表示」がオフのときは、形を選べない・ギズモも出ない。

### 対になる骨の名前(左 ⇔ 右)
次の順に調べる。見つからなければ、ユーザーが選ぶ(中央の骨など)。
1. 終わりが `.L / .R`・`_L / _R`(小文字も)。Blender の連番(`Arm.L.001`)があっても、よい
2. `Left / Right` を含む(`left / right`・`LEFT / RIGHT` も)。例:`mixamorig:LeftHand` ⇔ `mixamorig:RightHand`
3. `左 / 右` を含む。例:`左腕` ⇔ `右腕`

### 左右反転の計算
形は、骨の中の座標で持つので、次の順に直す(`MirrorHitbox`。`Animation/HitboxMirror.h`)。
1. 形の位置・向きに、**元の骨の行列**を掛けて、モデルの座標にする
2. **X を反転**する
3. **対の骨の行列の逆**を掛けて、対の骨の中の座標に戻す

骨の行列は、2 つとも**基準姿勢**のもの(動きを再生していても、反転の結果は変わらない)。**箱の向き**:X を反転すると、座標の右手・左手が入れ替わり、回転では表せない。そこで、箱の軸のうち **X の軸の向きを、逆にして、回転に直す**。箱は、軸の向きを逆にしても同じ形(面の位置・大きさが同じ)なので、見た目は、鏡映しのまま。大きさ(半分の大きさ・半径)は、変わらない。

## 設計メモ(なぜ、そうしたか・選ばなかった案)
- **ギズモは、外部ライブラリ ImGuizmo を使う(ツールだけ)**。最初は、自作の予定だった(矢印の描画・ホバー・レイと軸の最短距離の計算を、自分で書く)が、2026-10-08 に、**Ryusei が、ImGuizmo に変えた**。
  - 選んだ理由:移動・拡大のギズモと、ドラッグの操作感を、すぐに得られる。回転のギズモも付いている(今は使っていないが、形の向きの編集を足すときに、そのまま使える)。
  - 選ばなかった案(自作):判定の形の持ち方(中心・半分の大きさ・半径)に、そのまま合わせられる。依存が増えない。ただし、矢印・つまみ・ホバー・ドラッグの計算を、全部書く必要があった(見積もりは 5 タスク)。
  - デメリット:ImGuizmo は、**行列**で扱うので、形の中心・向き・大きさを、行列にして渡し、結果を、骨の中の座標に直す変換が要る(`DrawGizmo`)。右手系前提で、このエンジンは左手系 → **軸の自動反転(`AllowAxisFlip`)を切った**(視線の向きの判断を誤るため)。矢印は、いつも +X・+Y・+Z を向く。
  - 入れ方:`tools/AnimationEditor/CMakeLists.txt` で、FetchContent(コミットの番号で固定)。**このツールだけが使う**(エンジン本体・ゲームには入らない)。ImGuizmo 自身の `CMakeLists.txt` は使わず、取得だけして、自分でライブラリを定義している(ImGui と同じやり方)。
- **形を選ぶのに、レイを使う**(`Camera::ScreenPointToRay` → `Raycast`・`RayToSegmentDistance`。[Collision.md](Collision.md))。形を、画面に投影して、点が中に入るかを調べる案もあったが、箱・球・骨の線分を、同じ方法(光線との距離)で扱えるので、レイにした。
- **クリックとドラッグの見分け**:押した点から 4 ピクセル以上離れたら、ドラッグ(途中で戻っても、ドラッグ)。左ドラッグは、カメラを回すのに使っているので、クリックだけを「選ぶ」にした。
- **大きさのギズモは、世界の大きさの「比」を掛ける**:ギズモが返す大きさ(世界)を、そのまま使わず、「今の大きさとの比」を、骨の中の大きさに掛ける。骨やモデルに拡大があっても、値が合う。球は、一番大きく変わった軸の比を使う。
- **画面の確認は、確認ログでできない部分がある**:ドラッグ・クリックの見た目は、実機で確認する。答えが分かる計算(レイ・クリックの見分け・移動量の変換・大きさ・左右反転・名前の組)は、起動時の確認ログ(`RunCollisionSelfTest`)で検査する。

## 保存先と、ゲームとの関係
- 保存先は、**開いているアセットのフォルダー**の `Models/` の下(モデルの隣)。エンジンの `KR::SetAssetRoot` で、読み書きの場所を切り替えているので、別のゲームのフォルダーを開いて、そのゲームのフォルダーに保存できる。Debug でも Release でも、同じ。
- ゲーム側は、`AnimatedModel::Load("Boss/Boss.glb")`(または `"Boss/Boss.fbx"`)で、同じ場所の `Boss.hitboxes.json` を読む。ファイルが無ければ、骨ごとの、とりあえずの形になる。
- **同名の `.glb` と `.fbx`(拡張子だけが違う)は、同じ `Boss.hitboxes.json` を共有する**(保存先は、拡張子を `.hitboxes.json` に置き換えた名前)。骨の名前が同じなら、どちらを開いても、同じ判定の形が出る。**骨の名前が食い違うと、その骨の判定は、飛ばされて、警告が出る**(落ちない)。ツールで `.fbx` を開いて保存しても、同じファイルに書かれる。
- 骨は、**名前**で探す(無ければ番号)。Blender で、骨の名前を変えたら、保存し直す。

## 未保存の変更
形を変えると、「* 判定の形が、保存されていません」が出る。保存せずに、別のモデルやフォルダーに切り替えようとすると、確認の窓が出る(保存して続ける / 捨てて続ける / やめる)。

## まだ、できないこと(次の段階)
- 形の向き(回転)を、ギズモで変える(ImGuizmo には、回転のギズモがあるので、足せる。今は、向きは、ファイルの値のまま)
- 元に戻す(Undo)
- 骨そのものの編集(骨は、Blender で作る)
- 動きの、ブレンド・イベント

## FBX を開くときの注意
- 開けるのは、`.fbx`(バイナリ・ASCII。メッシュ + 骨 + スキン + 動き)。マテリアル・画像は、読まない。ほかは、glTF と同じように使える(骨を選ぶ・判定の形を動かす・保存する)。
- **骨とメッシュが、離れた場所にある FBX**(Blender で、アーマチュアとメッシュの置き場所が違う)は、起動時のログに、警告「骨とメッシュが離れています」が出る。判定の形は、**骨の位置**を基準に出るので、メッシュから離れた所に出る。**Blender で、アーマチュアとメッシュを原点にそろえて(Apply Transform)、書き出し直す**。ローダーは、補正しない(ファイルの意味を変えない)。
- 動きは、1 秒に 30 回の Linear に焼き付けて読む(元の曲線の補間は、ufbx が評価する)。骨に付かないメッシュ(判定用の立方体など)は、骨に付いたメッシュがあるファイルでは、読み飛ばす(ログに出る)。
- 詳しい経過・確認した物・保留している物は、[Animation.md](Animation.md) の「FBX 対応」。
