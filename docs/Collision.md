# 当たり判定(OBB。判定と、箱の表示)

自機と障害物が、**重なっているか**を、箱(OBB)で判定して、**箱を、線で描いて、確かめる**仕組み。この段階では、**判定だけ**(当たったあとの処理=ゲームオーバーは、あとで作った。GameOver.md)。

## OBB と、分離軸定理(Engine)

**OBB**(Oriented Bounding Box)は、**向きを持てる箱**。`中心`・`3 本の軸`(右・上・前。長さ 1・互いに直角)・`半分の大きさ`で表す。回転しない箱も、軸を (1,0,0)(0,1,0)(0,0,1) にすれば、**同じ形で持てる**(同じ関数で判定できる)。

たとえ:**2 つの箱を、いろいろな方向から、懐中電灯で、照らして、壁に、影を落とす**。**1 方向でも、2 つの影に、すき間があれば、2 つの箱は、離れている**。全部の方向で、影が、重なっていたら、箱は、ぶつかっている。

```
Intersects(A, B):
  調べる軸(15 本):A の 3 軸 + B の 3 軸 + A の軸 × B の軸 の外積 9 本
  軸ごとに:2 つの箱を、その軸に投影した「影」にすき間があるか
     すき間がある  → return false(当たっていない)  ← 1 本でも見つかれば、そこで終わる
  15 本すべてで、影が重なっていた → true(当たっている)
```

- **途中で、終われる理由**:すき間のある軸が、**1 本でも**見つかれば、「当たっていない」が確定するから。「当たっている」は、15 本すべてで、重なったときだけ。
- 外積の 9 本は、**辺と辺が、すれ違う向き**(面の向きだけでは、見つからない、すき間を見つける)。平行な外積(長さが、ほぼ 0)は、向きを持たないので、飛ばす。
- `MakeOBB(中心, 半分の大きさ, 回転行列)`:回転行列の 1〜3 行目を、箱の軸にする。**描画と同じ回転を渡せば、見た目と判定の向きが、そろう**。

| 関数 | 内容 |
|---|---|
| `OBB` | 中心・3 本の軸・半分の大きさ |
| `MakeOBB` | 回転行列から OBB を作る |
| `Intersects(A, B)` | 分離軸定理で、重なっているか |
| `GetCorners(OBB)` | 8 つの角(番号のビット 0 = 右・1 = 上・2 = 前)。線で描くときに使う |

## 線の描画(Engine)

箱を、**線**で描いて、見える化する(デバッグ用)。

```
Game:   DrawWireBox(OBB, 色)  → GetCorners で 8 つの角 → 12 本の辺 → DrawLine(始点, 終点, 色) を 12 回
        DrawLine は、頂点を 2 つ、積むだけ(その場では、描かない)
Renderer::EndFrame:  形(DrawMesh)を描いたあとに、ExecuteLines
        積んだ頂点を、今のフレームの頂点バッファに書き、線のパイプラインで、1 回で描く
```

| 項目 | 内容 |
|---|---|
| シェーダー | [Line.hlsl](../shaders/Line.hlsl)(位置と色だけ。光・フォグなし) |
| パイプライン | `DX12PipelineDesc::lines`(LINE で組み立てる)。深度あり。Root Signature は、物と空と、共有。F10 の再読み込みにも乗る |
| 上限 | 1 フレームに、32,768 本。超えた分は、描かない(警告) |
| 頂点バッファ | フレームインフライトの数だけ持つ(GPU が読んでいる途中で、書き換えないため) |

**線を、積んでおいて、最後に、まとめて描く理由**:GPU への命令は、1 回ごとに重いので、まとめて 1 回で送るほうが、軽い。

## 判定と表示(Game)

```
OnUpdate:  m_ChunkManager.Update → SyncChunkMeshes → UpdateCollision()
   ① 自機の箱
        回転 = 描画と同じ:RotationY(向き)→ RotationZ(バンク)→ RotationX(−機首)
        中心 = 自機の位置 + playerYOffset + 「回した playerCenter」(傾くと、箱の中心も一緒に動く)
        半分の大きさ = CollisionSettings の playerHalfSize
        → m_PlayerBox = MakeOBB(…)
   ② 置いてある全部の障害物
        中心 = (x, groundY + 高さ / 2, チャンクの startZ + z)      ← 形を作るとき(ChunkMesh.cpp)・描くとき(OnRender)と同じ式
        半分の大きさ = size / 2。回転なし(MakeOBB の回転は、単位行列)
        hit = Intersects(m_PlayerBox, 障害物の箱)  → 当たった数 m_HitCount
   ③ 自機の前後 drawRange 以内の障害物は、m_DebugBoxes に(箱, hit)を積む
OnRender:  showBoxes なら
        DrawWireBox(m_PlayerBox, m_HitCount > 0 ? 赤 : 緑)
        m_DebugBoxes の各箱:DrawWireBox(箱, hit ? 赤 : 緑)
OnImGui:   「当たっている:はい / いいえ(○ 個)」・チェックボックス・箱の大きさ / 中心のずれ・描く距離
```

**描画と同じ回転を使う理由**:箱の向きが、見た目と、ずれると、「当たっていないのに、当たっている(または、その逆)」になる。回転を、同じ式にすると、傾いたまま、角をかすめても、見た目どおりに、判定される。

> **追記(feature/auto-chunk)**:障害物の箱は、`ComputeObstacleBox(障害物, 向き)`(Course.h)で作る。見た目の形と同じ関数なので、縦長 / 横長の切り替え(AutoChunk.md)でも、ずれない。箱の中心の X には、列の中心(`ActiveChunk::startX`)を足す。

**障害物の箱を、回転なしにする理由**:障害物は、見た目も、回転していない(軸にそろった箱)ので、判定の箱も、そろえる。

**`m_DebugBoxes` を使う理由**:箱を作る計算(`MakeOBB`)は、`UpdateCollision` で、すでにした。`OnRender` は、その結果を、描くだけ(同じ計算を、2 回しない)。

**障害物の箱も赤にする理由**:障害物が、たくさん並んでいるとき、自機の箱が、赤になっただけでは、**どの障害物に、当たったのか**、分からない。

### 設定(`CollisionSettings`。settings.json の `collision`)

| 項目 | 初期値 | 意味 |
|---|---|---|
| `playerHalfSize` | (1.16, 0.24, 1.18) | 自機の箱の、半分の大きさ(m)。player.obj の範囲(X −1.00〜1.01・Y −0.16〜0.25・Z −1.02〜1.04)に、足もとの移動 +0.16 と、拡大 1.15 をかけた値 |
| `playerCenter` | (0.01, 0.24, 0.01) | 自機の位置(足もと)から見た、箱の中心のずれ(回転する前。m) |
| `showBoxes` | true | 箱を、線で描くか |
| `drawRange` | 50 | 箱を描く、自機の前後の距離(m) |

初期値は、数字を、コードに、書き込まず、**設定**にした。見た目と合っているか、見ながら、ImGui で調整して、保存できる(ビルドし直さずに、変えられる)。

## 球と、骨に追従する判定の形(ボーンアニメーション A-6)

| 追加した物 | 内容 |
|---|---|
| `Sphere`・`Intersects(Sphere, Sphere)` | 中心の距離 ≦ 半径の和(2 乗のまま比べる。ちょうど接するときも当たり) |
| `Intersects(Sphere, OBB)`・`Intersects(OBB, Sphere)` | 箱の上で、球の中心に一番近い点(箱の軸ごとに、中心からの距離を、± 半分の大きさに収めて求める)までの距離 ≦ 半径。球の中心が箱の中なら、距離 0 で当たり |
| `Renderer::DrawWireSphere` | 3 つの円(XY・YZ・XZ)の線(72 本) |
| `Hitbox`(Animation/Hitbox.h) | 骨にくっつけた形。位置・向き・大きさを、**骨の中の座標**で持つ(骨が動いても、数字は変わらない)。箱か球 |
| `EvaluateHitboxes(形, 骨の姿勢, モデル全体の行列)` | 世界の形(`WorldHitbox`)にする。行列 = (骨の中の向き・位置)× 骨の今の世界の行列 × モデル全体の行列。箱の軸は長さ 1 に直し、拡大は半分の大きさに掛ける。球は半径に最大の拡大を掛ける |
| `Intersects(WorldHitbox, WorldHitbox)` | 箱・球の 4 つの組み合わせを振り分ける |
| `GenerateDefaultHitboxes` | 骨ごとの、とりあえずの形(子がある骨 = 子までを覆う箱・先端 = 球) |

**骨のパレット(逆バインド × 世界の行列)を、判定に使わない理由**:パレットは、「基準姿勢の頂点を、今の姿勢に動かす」ための行列。判定の形は、骨そのものにくっつけるので、骨の今の世界の行列だけを使う(形の位置・向き・大きさを、骨の中の座標で持つため)。

**確認(ツール KRAnimationEditor)**:起動時に、答えが分かっている例(球×球・球×箱・回した箱)で `Intersects` を検査して、ログに OK を出す。骨に付いた形が、再生に合わせて動き、動かせる「テストの箱」に触れた形が赤になる。ファイルへの保存・読み込みは、ゲームで使う段階(A-7)で決める。

**判定の形の保存(A-7)**:`Hitbox` の一覧は、`AnimatedModel::SaveHitboxes()` で、モデルの隣の `<名前>.hitboxes.json` に保存できる(骨は、名前で探す)。使い方は [Usage.md](Usage.md) の 7-3。

## レイ(光線)と、画面から 3D の物を選ぶ(調整ツール A1)
マウスの位置から、3D の何に触れたかを調べるための部品。調整ツールで、形・骨を、クリックで選ぶのに使う(ゲームでも、同じ部品を使える)。

| 追加した物 | 内容 |
|---|---|
| `Ray`(Physics/Ray.h) | 始点と向き(長さ 1) |
| `Camera::ScreenPointToRay(x, y, 幅, 高さ)` | 画面の点(左上が (0, 0)・単位は画素)から、世界へ伸びるレイ。`XMVector3Unproject` で、near と far の 2 点を結ぶ。幅・高さは、**3D の絵を描いている領域の大きさ**(ツールでは、ImGui の `DisplaySize`)。始点は、カメラの前の面(near)の上 |
| `Raycast(Ray, Sphere)` | 当たれば、始点から当たった点までの距離 t(`std::optional<float>`)。2 次方程式 t² + 2bt + c = 0 を解く。**始点が球の中なら t = 0**・球が後ろなら、外れ |
| `Raycast(Ray, OBB)` | 箱の軸ごとに、2 枚の面の間(スラブ)に入る t の範囲を求め、3 軸の範囲が重なれば、当たり。始点が箱の中なら t = 0。回した箱でも、同じ |
| `RayToSegmentDistance(Ray, a, b, 出力の t)` | レイと線分(a → b)の最短距離。レイは、始点から前だけ(後ろには、伸びない)。細い物(骨の線)を、マウスで選ぶのに使う。出力の t は、レイの上で一番近い点までの距離 |

**なぜ、レイか**:箱・球・骨の線分を、同じ方法(光線との当たり・距離)で扱える。画面に投影して、点が中にあるかを調べる案は、形ごとに、投影の仕方を変える必要があるので、選ばなかった。

**確認(ツール KRAnimationEditor の起動時のログ)**:画面の中心・右端・左端・上端のレイの向き・球と箱への当たり(真ん中・外れる・後ろ向き・回した箱)・線分との距離(平行・交わる・端が近い・後ろ・レイ上の t)を、答えが分かっている例で検査して、OK をログに出す。
