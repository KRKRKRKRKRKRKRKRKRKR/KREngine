# エンジンの版(バージョン)の付け方

KR エンジンの版は、**メジャー.マイナー.パッチ**(例 `0.2.1`)。ドット(.)で、3 つの数字を区切る(セマンティック バージョニング)。
更新の記録は [CHANGELOG.md](../CHANGELOG.md)。

[← 資料の案内(Structure.md)に戻る](Structure.md)

## 3 つの数字
```
0 . 2 . 1
│   │   └ パッチ:バグ修正だけ(使い方は変わらない)
│   └──── マイナー:機能の追加(今までの使い方は、そのまま動く)
└──────── メジャー:互換性が壊れる変更(ゲームのコードを直す必要がある)
```
- 上の数字を上げたら、右の数字は **0 に戻す**(例:0.2.1 のあとに機能を足すと 0.3.0)。
- **メジャーが 0 の間は、開発中**。マイナーを上げるときに、互換性が変わることがある(その場合も、CHANGELOG の「ゲーム側で必要な変更」に書く)。`1.0.0` は、ゲームから見える API が、落ち着いてから。

## いつ、どの数字を上げるか
| 変更 | 上げる数字 | 例 |
|---|---|---|
| バグの修正だけ | パッチ | 日本語フォルダーで落ちる問題を直した |
| 機能の追加(今までの使い方は、そのまま動く) | マイナー | `AnimatedModel` を足した |
| ゲームのコードを直す必要がある変更 | マイナー(0.x の間)/ メジャー(1.0 以降) | `DrawMesh` の引数の順番を変えた |
| docs・内部の整理だけ(動きは、変わらない) | パッチ(または、版を上げずに、未リリースに書く) | CLAUDE.md の更新 |

## 版を出す手順(エンジンの、feature ブランチを merge するとき)
1. `CHANGELOG.md` の「未リリース」に溜めた変更を、新しい版の見出し(`## [0.3.0] — 日付`)の下に移す。**ゲーム側で必要な変更**があれば、必ず書く。
2. `CMakeLists.txt` の `project(KREngine VERSION 0.3.0 ...)` を、書き換える(**版の置き場所は、ここだけ**)。
3. ビルドして、起動のログの「KR Engine 0.3.0」が、変わったことを確かめる。
4. main に merge する。
5. **タグを付ける**:`git tag -a v0.3.0 -m "0.3.0: 変更の一言"`(merge したコミットに)。
6. push は、頼まれたときに。タグは、**別に** push する:`git push origin v0.3.0`(`git push` だけでは、タグは、送られない)。

## ゲームから見た、使い方
- ゲームのサブモジュールを、**タグで指す**と、「どの版を使っているか」が、一目で分かる:
  ```
  cd External/KREngine
  git fetch --tags
  git checkout v0.3.0
  cd ../..
  git add External/KREngine
  git commit -m "エンジンを 0.3.0 に進める"
  ```
- 進める前に、CHANGELOG の「ゲーム側で必要な変更」を読む。進めたら、ゲームをビルドして、起動して、確かめてから、コミットする。
- 今、どの版か:エンジンの起動のログの最初の行(`KR Engine 0.3.0`)・`KR::GetVersionString()`。
